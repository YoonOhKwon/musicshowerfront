# 의미 출력 소유권 원칙

이 문서는 Music Shower의 현재 의미 계층에 대한 최우선 계약이다. 기존 설계 문서와
충돌할 경우 이 문서를 따른다.

## 기본 원칙

- 프로젝트는 개발자가 정한 장르명 목록, 장르 조합표, 장르별 미학·인상 문구를
  음악의 정답으로 사용하지 않는다.
- 개발자의 자체 음원이나 사용자 음원으로 모델을 학습·미세조정하지 않는다.
  추론에는 출처가 확인된 사전학습 모델만 사용한다.
- 로컬 엔진은 측정과 상태 변화를 책임진다. 해석적 의미를 만들기 위한 장르 고정관념을
  측정값에 덧씌우지 않는다.
- 모든 후보는 `source`, `sourceFamily`, `sourceModel`, 근거와 확신도를 보존한다.

## 계층별 소유권

| 계층 | 허용되는 의미 생성자 | 금지되는 생성자 |
|---|---|---|
| FACT | 로컬 DSP/MIR/사전학습 분석 모델, Music Flamingo | 일반 언어 모델의 독자적 추측 |
| LIVE | 로컬 변화·이벤트 분석, Music Flamingo | 정적 수치의 변화 위장, 일반 언어 모델의 독자적 추측 |
| CONTEXT | 사전학습 로컬 장르 분류기, Music Flamingo, 두 기록을 받는 외부 판정 모델 | 프로젝트 장르 등록부·별칭표·조합표·장르별 문구표 |
| AESTHETIC | Music Flamingo가 낸 개념과 그 개념만 보존하는 외부 번역·표현 변환 | 로컬 축 규칙, 로컬 문구 사전, 일반 언어 풀 |
| IMPRESSION | Music Flamingo가 낸 인상과 그 인상만 보존하는 외부 번역·표현 변환 | 로컬 분위기 규칙, 로컬 문구 사전, 일반 언어 풀 |

한국어 표현 변환은 새로운 의미 생성으로 취급하지 않지만, 원본 Flamingo 개념의 범위를
넓히거나 장르·감정·장면을 추가해서는 안 된다.

## 장르 처리

1. 초기 장르는 로컬 사전학습 분류기의 현재 출력과 시간 기록을 사용한다.
2. 첫 Flamingo 청취는 로컬 후보를 보지 않는 블라인드 분석이다.
3. 이후 블라인드/보조 청취를 구분해 기록하고, 보조 청취를 독립 표로 중복 계산하지 않는다.
4. 복합 장르는 로컬 분류 기록과 Flamingo 기록이 실제로 수렴할 때만 승격한다.
5. 장르명은 모델 출력에서 그대로 온다. 로컬 JSON 목록은 허용 목록이나 이름 생성기로
   쓰지 않는다.
6. 최종 외부 LLM 판정기를 연결하기 전까지는 현재의 이름 불문 증거 결합기가 임시 판정기다.
   이 결합기는 새 장르명을 만들 수 없고 입력 모델이 제안한 이름만 순위화한다.

## 향후 Impression 결합

로컬 FACT/LIVE는 Flamingo IMPRESSION을 해석하는 추가 근거로 외부 모델에 전달할 수 있다.
이때도 로컬 엔진은 인상 문구를 만들지 않으며, 외부 모델은 원래 Flamingo 인상을 반박하거나
정교화할 수 있지만 측정 FACT를 변경할 수 없다.

## 런타임 안전장치

- 로컬 `impression-synthesis`, `local-grammar`, `aesthetic-induction`, `aesthetic-axis` 출력은
  화면 후보에서 차단한다.
- 정적 `evidence-gated-prior`, `genre-relation` 출력도 화면 후보에서 차단한다.
- 일반 언어 풀의 FACT/LIVE/AESTHETIC/IMPRESSION 출력은 마지막 공통 게이트에서 차단한다.
- Music Flamingo의 FACT/LIVE/AESTHETIC/IMPRESSION은 허용하며 직접 청취 출처를 유지한다.
